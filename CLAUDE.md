# Stride website: rules for Claude Code sessions

This repository is the Stride group website (Stride Social, Stride Talent, Stride Academy), built with Astro.
Stride Academy was Stride Education until 2026-11-10 (the owner's call): its name, its labels and its addresses (`/academy`, with `/education` redirecting) changed. In the code it is still `education` (the division key, `data-tone`, the collections, file and component names), and the Phase 2 documents still use the old name. The Insights category "Education" is a topic, not the division.
Stride Academy isn't open yet (the owner's call, 2026-11-10): `/academy` shows `education/ComingSoon.astro` on every screen (its passing light too since 2026-11-13; the words' turn towards the pointer needs a mouse): "Coming soon" and a button to `/talent/apply` (copy in `education.yaml`, `soon`). The full page (`education/EducationPage.astro`, `LevelMap`, the `stairs` deck) and its enquiry form (`pages/academy/_enquire.astro`; `/academy/enquire` redirects to `/academy`, `parkedRedirects`) are parked until it opens; don't link to its sections or its form meanwhile.
This repository, `mydigitalcrib/stride-social-web`, started fresh on 2026-11-16 from `stride-social`'s `fix/audit-cleanup` (the owner's call): the history before it, its tags (`phase-1-recreation`, `desktop-final`, `desktop-baseline-2026-11-13`), the old branches and the Phase 1 migration scripts (`scripts/migrate/`) stay in the private archive `mydigitalcrib/stride-social`. Where these files name one of those tags or an older commit, it is there.
Read `docs/phase-2/README.md` first. The approved plan lives in `docs/phase-2/`; treat it as the spec.

## Commands

```bash
npm install
npm run dev                  # http://localhost:4321
npm run build                # static build + content schema validation
npm run check                # astro check (types)
npm run check:links          # internal links and assets in dist/
npm run check:redirects      # every URL from the old sitemap resolves (docs/inventory/old-sitemap.txt)
npm run check:seo            # titles, descriptions, canonicals, OG, one h1, JSON-LD, sitemap
npm run check:placeholders   # unfinished placeholders in dist/ (add -- --strict for production)
npm run check:content        # Phase 3 content status + reference integrity (add -- --strict for launch)
npm run ci                   # everything CI runs
npm run test                 # browser tests (Playwright, Chromium + WebKit) against the built site on :4330
npm run test:desktop         # the approved desktop, compared with its baseline at 1280/1366/1440/1920/2560
npm run test:responsive      # phones and tablets (320–1024): no sideways scroll, no errors, the menu
npm run test:review          # REVIEW=1: screenshots to look at (test-results/review), REVIEW_PAGES / REVIEW_WIDTHS
npm run test:baseline:verify # the baseline is there and unchanged since it was approved
```

Visual tests: the desktop baseline (`tests/__baselines__`, out of Git; fingerprints in `tests/baselines.manifest.json`) is only replaced by `npm run test:baseline:approve -- --yes` (Playwright options after `--yes` narrow it; `--built-from <commit>` when the served build is older than the working tree), and only for a desktop the owner has approved. Pictures from other hosts are replayed from a recording made then. The page's clock is Playwright's, standing still from before the page opens (`tests/support/site.ts`), so timed motion lands the same on every run. `STRIDE_PORT=4331` tests a second build (`npx astro build --outDir dist-next`, served by the `astro-next` launch config) while `dist/` keeps serving the approved desktop.

## Content rules (non-negotiable)

- **Never invent** creators, follower counts, testimonials, campaign results, statistics, clients, logos, awards, offices or team members. If something is missing, ask, or use the `PlaceholderNotice` component (Phase 3). Never use fake data.
- Every figure needs a `source`; only `verified: true` results render.
- Creator profiles need recorded consent; brand logos need `approvedForDisplay: true`.
- Use the PDF headlines verbatim. Mark any copy you draft as `status: draft` until the owner approves it.
- Image fields always need meaningful `alt` text.
- Tone: confident, direct, human, brief. No filler words ("unlock", "elevate", "seamless", "cutting-edge").

## Workflow

1. Never commit directly to `main`. Create a branch: `content/<what>`, `feature/<what>` or `fix/<what>`.
2. Make the change, run `npm run ci`, and for visual changes screenshot the affected page at 1440px and 390px.
3. Open a pull request using the template. A reviewer approves the preview before merging.
4. Do not push, merge, deploy or touch the live Webflow site unless the owner explicitly asks.

## Code conventions

- **Pages** use `src/layouts/SiteLayout.astro`, tokens from `src/styles/system/tokens.css`, and components from `src/components/core/` (primitives), `src/components/global/` (header, footer, breadcrumbs) and per-area folders (`home/`, `social/`, `talent/`, `education/`, `group/`). Navigation lives in `src/config/navigation.ts`; form fields in `src/config/forms.ts`; collection routes in `src/lib/routes.ts`. Forms use `core/FormShell` + `core/Field`/`core/CheckboxGroup` (behaviour in `src/scripts/system/form.ts`). Brand briefs and creator applications are not the site's own: `/social/enquire` and `/talent/apply` redirect to Stride OS's forms (`formRedirects` in `scripts/redirects/map.mjs`; the owner, 2026-11-10), and so does `/talent/enquire`, Talent's brand enquiry, to the brand form (the owner, 2026-11-13: its page and Talent's "Book a creator." row are gone), so link to those routes as before and never to the Stride OS addresses directly; the site's own pages for them are parked (`social/_enquire.astro`, `talent/_enquire.astro`, `_apply.astro`). What a visitor picked (the brief, the career plan) doesn't travel to Stride OS. Roster listings always go through `src/lib/roster.ts` (consent rule, and no creator without a photo); Academy items through `src/lib/education.ts` (availability rule).
- **Phase 1** was retired in Stage 8 (its pages redirect via `scripts/redirects/map.mjs`; code at git tag `phase-1-recreation`). Editor guide: `docs/EDITING.md`.
- `plannedPages` (navigation config) is empty: every sitemap page exists. A future page can be listed there to get a labelled placeholder until it ships.
- Mark interim or missing content with `core/PlaceholderNotice` (it sets `data-placeholder`, which the placeholder check detects).
- Astro components with scoped `<style>`; breakpoints follow the design system: desktop from 1024px, tablet 768–1023px, phone up to 767px (`styles/system/tokens.css`). The desktop design is final (git tag `desktop-final`, the owner, 2026-11-13): new tablet and phone styles go inside `max-width` blocks and never change a rule desktop reads. Phones and tablets look the same as desktop (the user, 2026-11-13: the same composition, animations, fonts, colours and content, optimised for the screen, an animation dropped only where a phone couldn't keep it smooth): a component shares its desktop rules by turning a desktop-only block into `@media all` (the same rules, so desktop doesn't change) and then sizes and arranges for the screen in `max-width` blocks; what follows a pointer gets a touch equivalent (a first tap aims or chooses, a second acts; or the item in the middle of the screen), and the interface's pointer words ("Click to…", "Point at…") say "Tap…" on a touch screen (`tapWords` in `env.ts`, where a script shows them). Only the meteors (Social), the pointer's tilts and the hand-tracking camera stay desktop's. Scripts take the queries and the small shared helpers (`reduced()`, `desktop()`, `lenis()`, `clamp()`, `DESKTOP`, `TABLET`, `PHONE`) from `scripts/system/env.ts`; inline page scripts (`is:inline`) can't import, so they write the query out.
- Division context comes from `SiteLayout`'s `division` prop (`data-division` on `<html>`).
- One colour per division: Social `ice`, Talent `deep`, Academy `slate`; Group pages keep their own. Lime is for Talent's buttons only (`--press`, `--press-on`, `--press-hover`), never a background or accent; the one exception is Talent's name in the homepage intro. Every button on the site is glass (the owner, 2026-11-12, desktop; phones and tablets too since 2026-11-13): the edge menu's glossy capsule as the `--gb-*` recipe in `styles/system/glass.css`, brighter for the ways forward (`.exp-pill`, primary buttons, a deck's link, closing links), fainter for the quieter ones (ghost pills, secondary buttons, round arrows, chips, the chat's answers); a component whose styles go deeper uses the variables; words styled as big type (Insights' topics, Team's departments) opt out (phones had solid buttons, lime on Talent's, until 2026-11-13).
- Colour: the nine-colour palette is in `src/styles/system/tokens.css`. A section says its division (`data-tone`) and the palette colour it lives in (`data-look`, optionally `data-to`) and paints no solid background of its own: the page's background is one layer that follows the scroll along the palette (`src/scripts/system/backdrop.ts`). Text, hairlines and glass use the live tokens (`--ink`, `--hair`, `--fill-k`, `--tone-lit`, `--tone-on`), never literal white, so they work on any colour; anything on a photo or video goes in `.on-photo`. Where a style does need a fixed palette colour, it uses the token, never the numbers: `var(--white)`, `var(--navy-900)`, `var(--ice)`, and with an alpha their channels, `rgb(var(--white-rgb) / 0.4)`, `--navy-900-rgb`, `--ice-rgb`; a lit title's sheen is `--title-sheen`.
- Large screens (the owner, 2026-11-12: laptops to 8K, ultrawide and TVs, same designs): the design is drawn at 1920×1080 and grows with a bigger screen. On desktop the root size is `clamp(1rem, min(100vw / 120, 100vh / 67.5), 4rem)` (16px up to 1920×1080; 2× at 4K, 4× at 8K), and the spacing and layout tokens are in rem (`--content-max`, a `--margin` that centres the content on wide screens; `styles/system/tokens.css`). So on desktop, size things in rem (exactly px / 16, so nothing changes at or below 1920×1080) or with the tokens, never fixed px, except hairlines; the stroke of outlined display type is in rem too. Script geometry in px multiplies by `uiScale()` / `deskScale()` (`scripts/system/scale.ts`); `<img sizes>` let big screens fetch big files. Shared motion: `--spring-soft` and `--spring-pop` (`motion.css`), press feedback, focus rings and the light on every glass button (`glass.css`, the `--gb-*` recipe), `[data-magnetic]` for a page's main calls to action (`motion.ts`), reveals with `data-reveal` / `data-reveal-lines`. Each component's header comment describes its own desktop motion. Registered custom properties (`@property`) apply to the whole page, so give them names of their own (`--shero-gx`, never `--gx`). Phones and tablets keep a 16px root (their own sizes in `max-width` blocks); the shared motion reaches them where a component shares its desktop rules.

- Content lives in `src/content/` (typed collections, schemas in `src/content.config.ts`). Pages never hard-code collection data.
- **Collections:**
  - taxonomies: `categories`, `industries`, `markets`;
  - `services`, `talentDivisions`, `educationTopics`, `educationExperience`;
  - `brands`, `team`, `testimonials`, `roster`, `work`, `insights`;
  - `milestones` (Our History), `roles` (Careers), `legal`, `sponsorships`, `pages` (page copy).

  Pages read these through helpers that apply the status rules (`src/lib/roster.ts`, `src/lib/education.ts`).
- Respect the status fields when rendering: show results only when `verified`, roster profiles only with confirmed consent in production (`legacy` also in preview), logos only when approved, Academy items only with a confirmed availability, milestones only when verified, roles only when open. Never upgrade a status without Stride's confirmation.
- Keep JavaScript minimal (vanilla TS modules in `src/scripts/`), and respect `prefers-reduced-motion`.
- Keep components readable: match the surrounding naming and comment density.

## Gotchas

- Letters filled with a photograph (`background-clip: text`, as the division picker's) take no `filter` and no `text-shadow`, an inherited one included (TalentWall gives the smaller words a navy glow): Chrome draws a changing filter as the whole photograph, unclipped, and paints a shadow over the photograph, so the letters look dark. Fade them on a holder's `opacity` and set `text-shadow: none` on them.
- `duplicade-stride/` is a local Phase 1 backup. It is git-ignored; never edit it or reference it from the site.
- Images: reference originals under `/assets/...`; the build adds WebP `srcset` (integrations/responsive-images.mjs). Set `sizes` on `<img>` for anything narrower than the viewport. The first build generates the sizes (a few minutes); later builds use the cache.
- Preview builds (anything but `PUBLIC_SITE_ENV=production`) are noindex everywhere by design.
- Media: images live in normal Git; video files (`*.mp4`, `*.webm`) are tracked with Git LFS. Run `git lfs install` once per machine.
- Windows: run `git config --global core.longpaths true` before cloning (some asset paths are long).
- The old site's content issues (typos, duplicated sentences in some case studies) are documented in `docs/ARCHITECTURE.md`. Fix them only when asked.
